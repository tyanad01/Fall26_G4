## 1. Project Overview
The School System Website is designed to organize school information in one interface. The proposed system includes student, course, faculty, student-course, faculty-course, and building records. The prototype will show how users can navigate the website and access the main sections.

## 2. Intended Users
- **Administrators:** Manage school records and maintain information.
- **Faculty Members:** Access relevant faculty and course information.
- **Students:** Access relevant student and course information.

## 3. Visual Design
The proposed interface uses a soft pink and white color scheme. The navigation bar uses pink (#ff99cc), and the page background uses light pink (#fef6fb). The Poppins font provides a consistent look. Buttons, forms, headings, and navigation links should be clear and easy to read.

## 4. Prototype Screens

### Login Screen
The login screen will provide fields for a username or email and password, along with a login button. It will serve as the entry point to the website.

### Dashboard
The dashboard will provide navigation to the major database sections and help users understand which areas of the system are available.

### Student Management
The student screen will display student ID, first name, last name, address, email, phone number, and major. It will illustrate how student records could be viewed and managed.

### Course Management
The course screen will organize course information and provide a clear layout for viewing course records.

### Faculty Management
The faculty screen will organize faculty information and provide a consistent record-management layout.

### Student-Course Management
This screen will represent the relationship between students and courses, helping users understand which students are associated with which courses.

### Faculty-Course Management
This screen will represent the relationship between faculty members and courses, helping users understand course assignments.

### Building Management
The building screen will organize information about school buildings in a dedicated section.

## 5. Navigation and Usability
The prototype will use a consistent navigation bar and clearly labeled sections. Forms should group related fields together, and buttons should have understandable labels. The layout should remain consistent across all database screens.

## 6. Prototype Scope
This document describes the planned prototype. Screenshots, mockups, or Figma designs should be added to the project folder as they are created. Features should only be described as implemented if they have actually been built and tested.

## 7. Conclusion
The prototype will demonstrate the planned structure, navigation, and visual design of the School System Website. It will provide a foundation for reviewing the interface before further development.
